# Console dock tabs

## Request

Allow agent console tabs to be pulled into their own splits while keeping all console sessions grouped under a single level-1 workspace tab, next to Dashboard and project tabs.

## Requirements

- R1: Opening an agent session creates or focuses a level-1 Consoles tab instead of adding each terminal directly to the main workspace.
- R2: The Consoles tab hosts a nested Dockview so individual console tabs can be dragged/split within that tab.
- R3: Opening the same session twice focuses the existing console tab.
- R4: Existing terminal lifecycle, output replay, focus/input, resize, stop-on-close, and revert behavior stay inside `TerminalPanel`.
- R5: The change is frontend-only and must not change Tauri commands, PTY launch, session validation, or WSL routing.

## Non-Goals

- No external detached OS windows.
- No multi-window persistence.
- No new agent launch policy.
- No backend session contract changes.

## Assumptions

- "Sacar las tabs de consola" means users can drag console tabs out into splits inside the Consoles level-1 surface. True OS-window popout is out of scope because the existing Dockview app does not expose an app-window detach pattern.
- A single Consoles level-1 tab is acceptable even when the active workspace tab is a Dashboard or project tab.
