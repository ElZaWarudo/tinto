# WSL filesystem events

## Context
Local repos emit `tinto://fs-events` from the native watcher. WSL repos currently refresh git status and subscribed diffs through bounded polling, but they do not emit Plane 2 file event batches. That leaves mixed Windows/WSL workbenches visually uneven: WSL repos update their status, but the recent file-event stream and activity signals are local-only.

## Decision
Add an agent-side file fingerprint snapshot request. The Windows bus will compare each WSL repo's current Linux file fingerprints with the previous poll and emit `FsEventBatch` for created, modified, and removed files. This keeps the current one-shot `tinto-agent` model intact while making WSL repos participate in the existing event contract.

## Acceptance Criteria
- WSL repos can emit `tinto://fs-events` with the existing `FsEventBatch` shape.
- Initial WSL fingerprint load primes state without emitting a fake flood.
- Created, modified, and removed files are detected by relative path plus size/mtime fingerprint.
- `.git` internals are excluded and repo traversal remains allowlisted to active WSL repos.
- Existing local watcher behavior remains unchanged.
- Protocol message limits are compatible with existing WSL media previews and bounded fingerprint responses.

## Open Questions
- Native long-lived inotify streaming inside WSL remains a future performance upgrade. This package targets contract parity and visible event behavior without changing the agent transport model.
