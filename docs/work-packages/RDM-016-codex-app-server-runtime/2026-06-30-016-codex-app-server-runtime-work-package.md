# Codex App Server Runtime

## Scope
Implement a Codex app-server-backed agent runtime for Tinto sessions. The runtime should start Codex turns, stream output, consume app-server turn/change notifications, and close Agent Lens checkpoints through structured Codex lifecycle events.

## Implementation Evidence

- WSL fork worktree backend continuation (2026-07-02): WSL `/fork`, `/branch`, and `/lateral` now use a Linux-side `CreateGitWorktree` request when the source WSL session is active or an isolated worktree is explicitly requested. The WSL agent verifies the source repo is allowlisted, requires a valid `HEAD`, creates a detached worktree under Linux `$HOME/.tinto/worktrees/<repo-hash>/fork-<session>-<uuid>`, and returns the path to the host. Tinto then registers that path through `add_wsl_repo`, reseeds the bus, and starts the child WSL session in the isolated worktree. If starting the child session fails after provisioning, Tinto removes the WSL workbench entry and sends `RemoveGitWorktree`; the Linux agent only removes targets under its Tinto worktree root. `CreateGitWorktree`/`RemoveGitWorktree` are intentionally not retry-safe because they mutate Git/filesystem state.
